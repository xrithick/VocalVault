# 🎤 VocalVault – Singer Practice Tracker

A clean, modern web application designed for singers to organize their vocal repertoire, log daily practice sessions, and track their vocal progress.

**100% Pure HTML, CSS, and JavaScript. No Python, no servers to manage. Hosted completely free on GitHub Pages and connected directly to Supabase PostgreSQL.**

---

## 🗄️ Supabase PostgreSQL Setup (Required First Step)

VocalVault requires **3 tables** in Supabase: `users`, `songs`, and `practice`.

### Step 1: Create a Free Supabase Project
1. Go to **[https://supabase.com](https://supabase.com)** and create a free account (or log in).
2. Click **New Project**, choose a name (e.g. `VocalVault`), and set a database password.

### Step 2: Run the SQL Schema
1. In your Supabase project dashboard, click **SQL Editor** on the left menu.
2. Click **New Query**.
3. Copy and paste the following SQL script:

```sql
-- 1. Create Users Table
CREATE TABLE IF NOT EXISTS users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Create Songs Table
CREATE TABLE IF NOT EXISTS songs (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT REFERENCES users(id) ON DELETE CASCADE,
    song_name VARCHAR(255) NOT NULL,
    artist VARCHAR(255) NOT NULL,
    language VARCHAR(100) NOT NULL,
    difficulty VARCHAR(50) NOT NULL, -- 'Easy', 'Medium', 'Hard'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Create Practice Table
CREATE TABLE IF NOT EXISTS practice (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT REFERENCES users(id) ON DELETE CASCADE,
    song_id BIGINT REFERENCES songs(id) ON DELETE CASCADE,
    date DATE NOT NULL DEFAULT CURRENT_DATE,
    minutes INTEGER NOT NULL,
    rating INTEGER CHECK (rating >= 1 AND rating <= 5),
    notes TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Permissions Setup (allows anon key to read & insert data)
ALTER TABLE IF EXISTS users DISABLE ROW LEVEL SECURITY;
ALTER TABLE IF EXISTS songs DISABLE ROW LEVEL SECURITY;
ALTER TABLE IF EXISTS practice DISABLE ROW LEVEL SECURITY;

GRANT ALL ON TABLE users TO anon, authenticated, service_role;
GRANT ALL ON TABLE songs TO anon, authenticated, service_role;
GRANT ALL ON TABLE practice TO anon, authenticated, service_role;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO anon, authenticated, service_role;
```
4. Click the green **Run** button. You will see `Success. No rows returned`. All 3 tables are now ready!

### Step 3: Get Your API Credentials
1. In Supabase, click **Project Settings** (gear icon at the bottom left) &rarr; click **API**.
2. Find and copy:
   - **Project URL** (e.g. `https://abcdefghijklm.supabase.co`)
   - **Project API Keys &rarr; anon / public** key (long string starting with `eyJhbG...`)

## 🔗 How to Connect Supabase to VocalVault

You have **two easy ways** to connect your Supabase database:

### Method 1: Connect Directly from the Web App (Easiest)
1. Open the website: `https://xrithick.github.io/VocalVault/`
2. Click **⚡ Connect Supabase** in the top navigation bar.
3. Paste your **Project URL** and **anon public key**.
4. Click **Connect & Test**.
5. You will see a green toast notification: `Connected to Supabase PostgreSQL database successfully!`
6. Now click **Register** &rarr; your account will be immediately hashed with bcrypt and saved into Supabase!

### Method 2: Put Credentials in `config.js`
Open `config.js` in your repository and paste your credentials:
```javascript
const SUPABASE_CONFIG = {
    url: "https://your-project-id.supabase.co",
    key: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
};
```
Commit and push to GitHub, and the web app will connect automatically on every visit!

## 🔒 Security

- Passwords are securely hashed using **bcrypt** in JavaScript (`bcrypt.js`) before sending to Supabase.
- Only the hashed password is stored in the `password_hash` column of the `users` table.
- Raw passwords are never transmitted or stored in plain text.
